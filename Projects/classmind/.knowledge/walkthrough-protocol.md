# Walkthrough Protocol — Domain Model Validation

> **This document is pre-registered and frozen. Once annotation begins, nobody edits it.**
>
> Not because a paper is being published tomorrow. Because when numbers surprise us, humans
> rewrite their memory of what they expected. Predictions written after the fact are not
> predictions. If something here turns out to be badly designed, record that in the results
> document and change it for the *next* run — do not edit this file.

## The question

Can the concepts in [domain-model.md](domain-model.md) survive contact with real classroom
speech — and can two people apply them the same way?

This is the first time ClassMind stops arguing with itself and starts arguing with the world.

## What tomorrow may and may not do

**May:** discover concepts. If a coherent cluster emerges that the taxonomy has no slot for,
that cluster is earned by evidence.

**May not:** invent concepts. Patching the model tonight to accommodate a case we thought of
tonight would protect the model from falsification, which is the one thing this exercise exists
to prevent.

Known example, logged in advance so it cannot be claimed as a discovery: *"late submissions
won't be accepted"* is neither obligation nor advice — it is a **condition on** a Commitment,
and the taxonomy has no slot for it. **Prediction:** policy-and-condition statements will form
a recognisable cluster inside the residual category. If they do, a fourth Ledger item type has
been earned. If they scatter, it has not.

---

## Materials

**Four consecutive lectures from a single course**, publicly available, genuine Hindi-English
code-switching, undergraduate level. NPTEL and university channels publish full series.

**Consecutive matters.** Four scattered lectures make the coreference count meaningless, because
cross-session reference is the only thing four lectures can measure that one cannot.

**Why public recordings rather than performing a lecture ourselves:** self-authored data would
confirm our own assumptions. We would unconsciously perform a lecture our model handles — hedge
the way we expect, announce deadlines in the shapes we already designed for. This is an internal
calibration exercise producing no published artefact, so public recordings are appropriate. **The
graded research dataset is a different thing entirely and still requires consented recordings
from a partner institution.** Do not blur the two.

## The unit of annotation

Settled by design, not discovered by experiment, because leaving it open would mean measuring
segmentation and taxonomy simultaneously and being unable to tell which failed.

> **One Observation is one thing a lecturer can confirm or deny with a single yes/no.**

The unit is derived from the product, not from annotation convenience: it is the unit a lecturer
attests. This means the annotation protocol and the product interaction validate the same
abstraction rather than two different ones.

### Segmentation rules

1. **Properties travel with their subject.** Deliverable, due moment, submission method, weight
   — all one Observation. Splitting them creates four attestations where the lecturer perceives
   one announcement, which attacks the time budget directly.
2. **A new subject starts a new unit** — even mid-sentence.
3. **Tie-break:** would splitting force the lecturer to answer the same question twice? If yes,
   do not split.

**Worked example.** *"Assignment 3 is due Friday. Please submit it on Teams. Late submissions
won't be accepted."* → **one Commitment** carrying deliverable, due moment and submission
method. If the lecturer says "no, Monday," that is a correction of one property, not a denial of
the unit. The final sentence is expected to land in residual (see prediction above).

## Procedure

| Step | What | Who | Est. |
|---|---|---|---|
| 0 | Confirm this file is frozen and committed before anything else begins | one person | 5 min |
| 1 | Select the four lectures; record URLs, course, lecturer, durations | one person | 20 min |
| 2 | Transcribe lecture 1 with whatever ASR is nearest to hand; record engine and version | one person | 20 min |
| 3 | **Independent extraction, lecture 1.** Two annotators, separate rooms, no guide, no discussion. Domain model glossary (Part 7) available; nothing else | two people | 45 min each |
| 4 | Compute boundary agreement and label agreement. **Do not discuss the transcript yet** | one person | 20 min |
| 5 | Write the two-page annotation guide. Two pages. Not twenty | both, together | 45 min |
| 6 | **Re-extraction, lecture 1**, using the guide. Independent again | two people | 30 min each |
| 7 | Recompute both agreement measures. Record the delta | one person | 20 min |
| 8 | Transcribe lectures 2–4. Single-pass extraction, one annotator | one person | 90 min |
| 9 | Mark every back-reference, and every case where the two annotators would *plausibly* disagree about identity | both | 30 min |
| 10 | Write results: observations first, interpretation second, decisions last | both | 45 min |

One long day. Step 5 is the only step where the annotators talk to each other before step 9.

---

## Instruments

Three measures, deliberately separated so they can fail independently.

**Boundary agreement** — did both annotators draw the same units? Compare unit spans; count a
match when spans overlap by ≥80% of the shorter one.

**Label agreement** — over units both annotators drew, did they assign the same type? Computed
only on agreed boundaries, so a segmentation failure cannot masquerade as a taxonomy failure.

**Hesitation** — every time an annotator pauses more than five seconds on a unit, they mark it
and note why. *Hesitation is not failure; it is evidence.* Two annotators can eventually agree
after thirty seconds of uncertainty, and agreement alone would score that as a success while
concealing that the concept is not yet natural. Expect the best improvements to the domain model
to come from these marks rather than from the disagreements.

Also recorded: elapsed annotation time per lecture, and how much discussion was needed at step 9
to reconcile.

| P2 | Label agreement, no guide | 50–65% |

communicated, not as evidence the model is excellent. Re-run with a fresh lecture.

## Criteria

Six. Each produces **observation → interpretation → decision**, in that order, kept in separate
sentences. A criterion is not permitted to state its own decision.

### C1 — Is the Observation/Commitment split necessary?

**Superseded reasoning, recorded so it is not silently reintroduced:** an earlier draft used
frequency — under 5% of references being back-references would collapse the split. That was
wrong. Low-frequency events can be high-importance: deadline extensions, cancellations and scope
changes are rare and are precisely what students care about most.

The replacement is not "do we lose explanatory power if we collapse the split?" either — that
returns *yes* every time and is therefore a justification, not a test.

**The actual test:** did the two annotators ever **disagree about whether two mentions referred
to the same commitment**?

- *Observe:* count of contestable coreference cases across four lectures.
- *Interpret:* a contestable case means the identity judgement cannot be made silently by code
  without risking a wrong answer that rewrites an unrelated commitment's due date.
- *Decide:* one or more contestable cases → the split is necessary at any frequency. Zero across
  four lectures → resolution is obvious enough to do implicitly, and P9's frequency becomes
  supporting evidence for a simpler model.

### C2 — Does the taxonomy have a significant residual?

- *Observe:* share of units assigned to none of Commitment / Notice / Guidance, and whether the
  misfits share a shape.
- *Interpret:* under 10% and scattered means the taxonomy is adequate. Over 10% and coherent
  means a concept has been discovered. Over 10% and heterogeneous means the taxonomy is wrong.
- *Decide:* per the interpretation above. **No new concept may be added unless the cluster is
  coherent.**

### C3 — Is the domain model legible to two people?

The criterion weighted highest, because a ubiquitous language exists to make independent people
model reality the same way. Testing whether the model matches reality is secondary to testing
whether two people apply it identically.

- *Observe:* the four agreement numbers (boundary and label, before and after the guide) and the
  hesitation marks.
- *Interpret:* a large jump from the guide means the concepts are sound and the vocabulary was
  introduced badly. A small jump means the taxonomy itself carries the ambiguity. The guide is an
  *instrument for measuring conceptual clarity*, not a permanent crutch — the concepts should
  eventually absorb it.
- *Decide:* large jump → keep the taxonomy, fold the guide into the glossary. Small jump →
  simplify the taxonomy, because concepts that only work with a manual will never be attested
  correctly by a lecturer who has read no manual.

### C4 — Is ASR adequate?

- *Observe:* error rate on obligation-bearing sentences specifically — those carrying dates,
  deliverables and requirements. Not overall word error rate.
- *Interpret:* can a human reading only the transcript extract the item correctly?
- *Decide:* if not, we would be measuring transcription rather than extraction, and the research
  question changes shape before any architecture is designed.

### C5 — Attestation cost *(decoupled — see below)*

- *Observe:* stopwatch time for a lecturer to rule on their own lecture's items, plus whether
  they answered from memory or had to reason.
- *Interpret:* answering from memory validates the *attest* framing; having to reason breaks it
  and means the interaction is review, not confirmation.
- *Decide:* under 8 minutes for a 40-minute lecture passes for an unoptimised paper test. Above
  ~20 minutes means the core domain has no viable producer and the product needs rethinking.

### C6 — Written verdict on each open question

Each of the five open questions at the end of `domain-model.md` gets a written verdict:
settled with its evidence, or explicitly *"unknown, proceeding with X, revisit at N lectures."*
No silent carry-forward.

---

## C5 must run separately

Criterion 5 cannot use a public recording — you cannot ask an NPTEL lecturer to attest to their
own lecture. It requires a real lecturer with their own material, which runs on someone else's
calendar.

**Run it in parallel. Do not block the other five on it.** Its absence delays one criterion, not
the walkthrough.

---

## Stopping rule

**Time-boxed, not sample-boxed. One day, four lectures.**

If the criteria do not settle, that *is* the finding. It means the model is too speculative for
the evidence available, and the correct response is to **simplify the model** — not to run ten
more lectures. A domain model requiring twenty lectures to validate is a domain model that is
guessing.

Nothing downstream — product architecture, navigation index, schema, dashboards, implementation
— begins until the results document exists.

## Data collection template

One row per unit. Two files for lecture 1 (one per annotator, filled independently), one file
each for lectures 2–4.

| Column | Meaning |
|---|---|
| `unit_id` | Sequential within annotator and lecture |
| `lecture_id` | Which of the four |
| `annotator` | Initials |
| `pass` | `no_guide` or `with_guide` |
| `start_time` / `end_time` | Position in the recording, mm:ss |
| `verbatim` | The words, exactly as transcribed. Do not clean |
| `unit_type` | `commitment` · `notice` · `guidance` · `residual` |
| `commitment_kind` | `assignment` · `quiz` · `exam` · `project` · `presentation` · blank |
| `deliverable` | What is required |
| `due_phrase` | The spoken phrase, verbatim — *"next Thursday"*, not a date |
| `due_resolved` | The absolute date, and the rule used to get there |
| `submission_method` | If stated |
| `refers_to` | `unit_id` of an earlier unit this one concerns, or blank |
| `refers_confidence` | `certain` · `probable` · `contestable` — **`contestable` is the C1 measure** |
| `hesitation_sec` | Seconds paused, if over five |
| `hesitation_why` | One line. This is where the model improves |
| `notes` | Anything that does not fit above |

Blank templates: `walkthrough/` (create at step 0).

## After

The results document leads with observations, then interpretations, then decisions — in that
order, never collapsed into one sentence. "68% agreement" is an observation. "The taxonomy plus
these instructions produced 68%" is an interpretation. "Simplify" is a decision that requires the
post-guide delta before anyone may say it.

Only then does anything get designed.

## A note for later

This protocol is an attempt to validate a **domain model** before any software exists — using
pre-registration, independent annotators, a before/after intervention, and separated instruments.
That may be a reusable method rather than a one-off.

It is not a method yet. It is an interesting idea that has not survived contact with reality. If
it works, capture it as a candidate pattern then, and not before.
